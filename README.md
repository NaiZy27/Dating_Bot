# NewDating — Telegram-бот знакомств

Учебный проект: бот знакомств в Telegram.

## Концепт

Знакомства прямо в Telegram, без отдельного приложения и регистрации. Пользователь заполняет короткую анкету и листает анкеты других. Кто понравился — получает лайк. Контакты раскрываются только при взаимной симпатии, поэтому никто не получает сообщений от тех, кто ему не интересен.

## Как это работает

1. **Анкета.** Имя, возраст, город, пол, кого ищешь, пара слов о себе и фото. Анкету можно редактировать и выключать.
2. **Поиск.** Бот показывает анкеты по одной: нужного пола, похожего возраста, тех, кого ты ещё не оценивал. На каждую можно ответить ❤️, 💌 (лайк с сообщением) или 👎.
3. **Лайки.** Человек получает уведомление «Ты кому-то понравился» и может посмотреть, кто его лайкнул.
4. **Мэтч.** Если симпатия взаимная, оба получают ссылку на профиль друг друга и дальше общаются сами.
5. **Безопасность.** На анкету можно пожаловаться. После жалоб от нескольких разных людей анкета пропадает из поиска, а модератор получает уведомление.
6. **Лимиты.** Лайки и письма ограничены: 30 в день и не больше 10 в час. Ответный лайк лимит не тратит.
7. **Премиум.** 100 лайков в день и никакого лимита в час. Кроме того, имя в анкетах из ленты становится ссылкой на Telegram, так что можно написать человеку без взаимного лайка. Оплата ненастоящая (mock): кнопка «Оплатить» сразу включает премиум, деньги не списываются.

Технически: aiogram 3, анкеты и лайки хранятся в PostgreSQL, временные данные (шаг диалога, лимиты) — в Redis.

## Структура

```
app/
├── __main__.py        # точка входа: python -m app
├── config.py          # настройки из .env (pydantic-settings)
├── loader.py          # экземпляры Bot, Dispatcher, Redis
├── db.py              # таблицы, миграции, запросы к базе
├── models.py          # Pydantic-модель Profile и её валидация
├── states.py          # FSM-состояния
├── keyboards.py       # клавиатуры
├── views.py           # общие экраны: главное меню, своя анкета
├── utils.py           # safe_send, contact_link, reaction_lock
└── handlers/
    ├── __init__.py    # порядок подключения роутеров + cleanup
    ├── common.py      # /start, «Создать анкету», «Отмена»
    ├── registration.py# шаги анкеты (они же для редактирования)
    ├── menu.py        # главное меню и меню редактирования
    ├── premium.py     # премиум через mock-оплату
    └── search.py      # просмотр анкет, лайки, мэтчи, жалобы
```

Порядок роутеров в `handlers/__init__.py` важен. `common` подключается первым, чтобы «Отмена» работала из любого шага. `fallback` подключается последним: он удаляет сообщения, которые не поймал ни один хендлер.

## Настройка

```bash
cp .env.example .env
```

В `.env` нужно указать как минимум `BOT_TOKEN` (токен от @BotFather). Остальные переменные описаны в `.env.example`.

## Запуск в Docker

```bash
docker compose up -d --build
docker compose logs -f bot
```

Compose поднимает Postgres и Redis, а бот ждёт, пока база будет готова. Адреса `DATABASE_URL` и `REDIS_URL` внутри compose подставляются автоматически, поэтому в `.env` их можно не менять. Данные хранятся в томах `pg_data` и `redis_data`.

## Локальный запуск

Нужны Python 3.11+ и запущенные Postgres и Redis.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app
```

Запускать нужно из корня проекта: `.env` читается из текущей папки.

Таблицы создаются при старте. Новые колонки и индексы добавляются через список `MIGRATIONS` в `app/db.py`.
